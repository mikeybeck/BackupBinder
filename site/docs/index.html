How a backup works here.

BackupBinder keeps a restic archive of a site on this machine. Restic is the program that stores the archive. Each successful run is a snapshot, and file data that has not changed is stored once.

A site is a directory of files. When an addon matches that directory, the backup can also include a database dump. WordPress is the addon that ships with the program. A directory that matches nothing is files only.

With no destination turned on, the backup stays on this computer. That backup is complete. A destination is an extra copy of the finished archive.

The program you build is named backupbinder.

  1. Install

    Build the program, put restic where it can be found, and open the browser on this machine.

  2. First backup

    Point it at a folder or a server, answer one step at a time, and see what the run stores.

  3. Restore

    Extract a snapshot into an empty folder and leave the live site alone.

  4. Schedules

    Call the program from cron, choose how many snapshots to keep, and cap the speed.

  5. Destinations

    Copy a finished archive to SFTP, a disk, S3, B2, or Google Drive.

  6. Agents

    Use the same commands from a script or over MCP, after naming the exact site.
