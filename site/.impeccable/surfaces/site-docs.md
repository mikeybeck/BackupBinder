# BackupBinder handbook (`site/docs/`)

<!-- impeccable:surface-brief -->

Mode: Read  
Primary target: `site/docs`  
Audience: someone with a folder or a server who wants a backup they can restore, including a person driving an agent  
Job: follow install, first backup, restore, schedules, destinations, and the agent rules without leaving the site  
Task: read the page that matches the question, then run the command it shows  
Content: facts from the product (README, command catalog, restore and retention rules). No invented customers, quotes, or benchmarks.  
Constraints: same filing cabinet as the landing; WordPress is one addon; a local archive is a complete backup; restore only into an empty scratch directory; plain speech, no slogan headings

## Direction contract

THESIS: The handbook is one folder from the same drawer, with a typed index and prose you can follow, so the docs read as the file inside the cabinet.  
OWN-WORLD: Inherited cabinet: graphite drawer `#2a2e35`, manila folder `#e8dcc8`, kraft tab `#c9a66b`, cream sheet `#f7f1e6`, stamp teal `#0d6b5c`, ink `#1a1c20`; Archivo labels, Source Sans 3 body; hard edges; no sidebar, no card grid, no new palette.  
STORY: The reader can install the program, take a first backup, restore into an empty folder, schedule it, copy the archive out, and hand the same commands to an agent.  
FIRST VIEWPORT: Sticky metal tabs for BackupBinder and Docs; one open folder whose tab names the page; a sentence title, a short lede, then a typed index of the handbook.  
FORM: Filing-cabinet folder, inherited from the landing (seed `8fd0c73e`).  
FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
